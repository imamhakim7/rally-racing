## Scope & trust boundaries

The change is a pure client-side data pipeline plus build/dev tooling. Boundaries considered:

1. Stage JSON document  ->  parseStage -> validateStage(schema) -> normalise -> StageCircuit
   -> buildStageWorld (THREE.Group) / toRaceStage().
   Today the JSON is bundled at build time through the generated `src/stage/data/index.ts`
   (static ESM imports). There is NO runtime fetch/import of external stage data in this
   build, so untrusted stage JSON is not a live reachable input. This is the format's
   intended future runtime/mod surface and the one boundary that matters long-term.
2. Stage name / biome -> DOM <select> (select.ts), and minimap colour -> (future HUD #APEX-10).
3. Dev-only screenshot static server (scripts/screenshot-stage.mjs) serving ./dist on 127.0.0.1.
4. Build-time index generator (scripts/generate-stage-index.ts) reading src/stage/data/.
5. Author CLI validator (scripts/validate-stage.ts) reading a path given by the operator.

   - accepted by the validator -> 800,001 cross-sections -> ~67 MB road geometry
   - amplification ~235,000x from the input file.

## Findings

LOW-1 (defence-in-depth, NOT blocking) — unbounded stage allocations.
`StageSchema` array fields define `minItems` but no `maxItems`, and numeric fields
(currently only some) have no upper bound; spline point coordinates have no magnitude bound.
A small JSON document can therefore request an arbitrarily large mesh (200 km @ 0.25 m ->
~67 MB; scaling the span/step further is bounded only by the authored values). Reachability
today is nil: stage data is bundled and trusted, parsed at build time, with no runtime
external input. Residual risk materialises only if/when a later ticket loads stage JSON from
a remote, user or mod source. Recommended (follow-up, not a blocker for #APEX-4): add
`maxItems` to `spline.points`/`checkpoints`/`surfaces`/`minimap.points`, clamp coordinate
magnitude and/or clamp the computed sample count in `sampleSpline`. Reference #APEX-4.

No Critical/High/Medium findings. No secrets, no new dependencies, no exploitable injection,
no authn/authz surface, no PII.

## Decision

PASS — security gate cleared. The single Low finding is latent and recorded as residual risk
with a follow-up recommendation; it does not block #APEX-4 because no untrusted stage input
path exists in this build.
